# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- Dependency audit gate with time-boxed, expiring exceptions (`audit-exceptions.json`, `osv-scanner.toml`); first exception: picomatch GHSA-fc5q-39xc-vjpf until 2026-12-17 (T-001, NFR-020).
- Repository tooling: npm workspaces, TypeScript (strict), ESLint, Prettier and Vitest with a coverage threshold (T-001).
- Pull-request pipeline with secret scanning, static analysis and dependency audits that fail the build (T-001, NFR-020).
- Renovate configuration for weekly grouped updates and immediate security updates (T-001).
- `packages/core`: the ten bilingual categories, the seven currencies with their decimal places and display symbols, Arabic-Indic and Eastern Arabic to Western digit conversion, and exact conversion between decimal strings and integer minor units (T-002, FR-014, FR-015, FR-022).
- Utterance parser, first part: transcript normalisation and the number grammar for Egyptian and Standard Arabic and English number words, digits in either script, halves, quarters and piastres, giving exact amounts (T-003, FR-025, NFR-002).
- Utterance parser, dates: today, yesterday, the day before yesterday, N days ago (1 to 30) and last <weekday> in Egyptian Arabic and English, counted back from an injected calendar date; future, unsupported or conflicting date expressions give today marked for attention, and a number inside a date expression is never taken as the amount (T-004, FR-027).
- Utterance parser, currency and amount choice: currency words for the seven supported currencies in Egyptian Arabic and English (unqualified pounds and piastres are EGP, sterling is GBP), with halves, quarters and duals for every currency ("خمسة دولار ونص", "دولارين"); the user's default currency when no currency word is said; a currency outside the list gives the default marked for attention; the amount next to a currency word is used, and two or more amounts mark the amount for attention (T-005, FR-028, FR-025).
- Utterance parser, categories and assembled result: a reviewable category keyword list for the nine categories other than Other, in Egyptian Arabic and English, with English words and brand names also in Arabic script ("supermarket" and "سوبر ماركت", "uber" and "اوبر"); words of five or more letters also match at one spelling edit; no category word gives Other marked for attention, and two different categories give the first said, marked. `parseUtterance(text, { language, defaultCurrency, today })` returns amount, currency, category, date, a per-field attention mark and the text; when nothing is understood, amount, category and date are all marked, and an utterance mostly in another language gives empty fields with every field marked. The parser returns data only, and a test fails if its source imports anything outside the parser or names a network or storage API (T-006, FR-026, FR-029, FR-030, NFR-008).
- Voice test-set manifests in `poc/voice`: 126 Egyptian Arabic sentences (30 with English words, 17 with piastres or fractions, 25 with relative dates) and 114 English sentences, each with the expected amount, currency, category and date against a fixed "today". They are drafts until the native-speaker review. Also a validator for fields, tags and the NFR-001 and NFR-003 composition, run by `npm test` and `npm run voice:validate`, and a parser-only score on typed transcripts, `npm run voice:score`, which writes `poc/voice/reports/typed-transcripts.md` (T-007, NFR-001 to NFR-003, FR-029).
- API Worker scaffold in `apps/api`: a Hono application on Cloudflare Workers with `routes/`, `services/`, `repositories/` and one `platform.ts` adapter. `GET /api/v1/health/live` and `/health/ready` (`SELECT 1` on D1 within 2 seconds, otherwise 503). Every response has a server-generated `X-Request-Id`; `/api` responses are `no-store`; errors are RFC 9457 problem details with a stable `code` and `request_id` and no internals; requests are refused, and the missing names logged, when `DB` or `RELEASE` is absent; one JSON log line per request holding allow-listed fields and values only. Drizzle configuration and an empty migrations folder. Tests run in the Workers runtime with a local D1 database through `npm run test:integration` (T-014, NFR-023, NFR-028, NFR-014).
- `GET /api/v1/config`, public: `{ googleClientId, termsVersion, privacyVersion, release }` for the clients, so one web build serves every environment. `googleClientId` comes from the new optional variable `GOOGLE_CLIENT_ID` and is `null` until one is configured; a value that is not shaped like a Google client id refuses every request and the log names the variable (T-016).
- OpenAPI description `apps/api/openapi.json`, generated from the route schemas with @hono/zod-openapi and committed; every route is registered through it, a test fails when a route is served but not documented, and the pipeline's lint stage fails when the committed file or the generated client types are out of date (`npm run openapi:check`). Invalid input to a route is refused with `400 validation_failed` listing the fields (T-016, NFR-016).
- `packages/api-types`: client types generated from `openapi.json` with openapi-typescript, and a small typed `fetch` client with `getConfig()`, a generic `request()` and problem-details errors as `ApiError` (T-016).
- API security layers: every response carries HSTS, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy` and the Content-Security-Policy from the architecture; CORS allows exactly `https://localhost`, without credentials; request bodies over 16,384 bytes get `413 too_large`, counted on the bytes received; routes are denied by default, with public routes listed in `apps/api/src/public-routes.ts` (T-015, NFR-019, NFR-020, FR-019).

- Web app scaffold in `apps/web`: a React single-page app built with Vite (target chrome111, firefox128, safari16.4) and served by the API Worker on the same origin. Routes from the architecture are declared, each with a translated placeholder; the home page shows the app name and the `release` from `GET /api/v1/config`, with translated loading and error states and the request id on error. English and Arabic throughout, with `lang` and `dir` set on `<html>`: the first visit follows the browser's languages (any Arabic variant gives Arabic, anything else English), a control on every screen switches at once without unmounting open forms, and the choice is remembered on the device (T-017, FR-020, FR-021, NFR-028).
- Interface texts for both languages in `packages/core/src/i18n`, with `npm run i18n:check` in the pipeline's lint stage: it fails when a text is missing or empty in either language, uses Arabic-Indic digits, or names different placeholders (T-017, NFR-009, FR-022).
- Lint rules: no literal user-facing text in web components (text and attributes such as `aria-label`, `title`, `placeholder`, `alt`), no physical CSS properties in style sheets (`@eslint/css`) or inline styles, no `dangerouslySetInnerHTML` (T-017, NFR-009).
- End-to-end, accessibility and screenshot harness in `apps/web/e2e` (Playwright 1.65.1, @axe-core/playwright 4.14.0): the API Worker serving the web build in local mode, driven in Chromium, Firefox and WebKit at 320 and 1,920 CSS pixels. A screen inventory (`screens.ts`) lists every screen and state; for each one, in English and Arabic, the run checks `lang` and `dir`, runs axe with the WCAG 2.2 A and AA rules and saves a full-page screenshot. A test-only pseudo-locale run fails on clipped or overflowing text. `npm run e2e` (also per engine); the pipeline runs it after the integration tests and uploads the report and screenshots (T-018, NFR-025, NFR-009, NFR-026, FR-020).
- Display formatters in `packages/core`: `formatAmount` and `formatAmountParts` give an amount in integer minor units as Western digits grouped with "," and exactly the currency's decimals (three for KWD), then the currency label: the code in English, ج.م for EGP in Arabic, the code for the other six in both ("1,234.50 EGP", "1,234.50 ج.م"); zero and totals above one expense's limit are accepted. `formatDate` gives a stored `YYYY-MM-DD` date as "16 Nov 2026" or "16 نوفمبر 2026", day without a leading zero, with month names from the interface texts (`date.months`). No `Intl`, no `toLocale*`, no date library; a lint rule refuses those APIs in `packages/core/src` and `apps/web/src` outside tests. Web helpers `<Amount>` (number in `<bdi dir="ltr">`) and `<UserText>` (`<bdi dir="auto">`, shown as typed) (T-045, FR-022, FR-015, FR-020).

- Privacy policy and terms pages at `/privacy` and `/terms`, public, in English and Arabic (right to left), each with its version and effective date and a "Draft for review" banner. Version 1 of both is a draft factual description of what the service does with data, from the requirements' Data table, the architecture and ADRs 0008 and 0009, with a marked gap for the legal text and a "contact address to be published" placeholder; it is not legal text. The documents live in `packages/core/src/policies`, one module per document and language, with a source map per section; a language whose text is missing or out of date shows a translated "not available" message and never the other language. The privacy policy links to the account deletion page (T-023, FR-039, FR-020, FR-009).
- A notice on every screen when a document's version differs from the one the device last saw, linking to each changed document, announced politely to screen readers, and dismissed by recording the current versions on the device; a first visit records the versions without a notice (T-023, FR-039).
- `npm run release:check-policies`: a release check that fails when either document lacks an English or Arabic text, a version or effective date is invalid, `GET /config` serves other versions than the documents, a document is a draft, or the contact address is a placeholder. It fails today by design and is not part of the pull-request pipeline (T-023, FR-039).

### Changed

- `GET /api/v1/config` now serves `termsVersion` and `privacyVersion` `"1"`, read from the policy documents in `packages/core`, instead of the `"0"` placeholders; the response shape is unchanged. The API now depends on `@masareef/core` (T-023, FR-039).

- Pages and files of the web build now answer GET and HEAD outside `/api`, through the same security layers as the API, instead of `404`; other methods there still get `404 not_found`. A path with an encoded slash after `api` (`/api%2Fv1/...`) is treated as an API path, so it gets `401` without a session rather than `404` (T-017, NFR-020).

- Without a session, an unknown `/api` path or a wrong method on a public path now gets `401 unauthenticated` instead of `404`, so an anonymous caller cannot tell which routes exist (T-015, FR-019).
- Utterance parser, fixes from the typed-transcript score (T-007a, FR-025, FR-026, FR-028, NFR-001 to NFR-003):
  - More Arabic number forms: "ميت", "مائتي", "ألفي" and fused thousands such as "خمستلاف"; "عشرة إلا ربع" is 9.75, "ألف ونص" is 1500 and "one and a half thousand" is 1500, all in exact decimals.
  - A bare number from 1 to 99 after a pound word is piastres when the utterance ends there ("خمسة جنيه وخمسين", "three pounds fifty"). With more words after it, only 25, 50 and 75 are, marked for attention; other numbers stay a second amount, so "خمسين جنيه وعشرين تاكسي" is still 50, marked. Piastres read this way after 100 pounds or more are also marked.
  - A number that counts things gives way to the price ("2 pizzas for 400", "two kilos of oranges for fifty", "3 months of internet, 750"); the amount stays marked. If it is the only number it is kept, marked.
  - With an explicit "each", "per" or "كل واحد", a whole count of two or more is multiplied by the unit price exactly, marked for the user to confirm.
  - "المية" after a bill or utility word is water, not 100.
  - Currency symbols are read before or after the number: "$" USD, "€" EUR, "E£" EGP, "﷼" SAR. "£" alone is EGP, like the word "pounds", but marked because it can also mean sterling.
  - Many more category keywords in Arabic and English, by family. They match exactly only; words too ambiguous to use are listed in the lexicon.
- The typed-transcript report now says it is a development score, tuned on the sentences it measures; the independent measure is the real-speaker test set (T-007a).
